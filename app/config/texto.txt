¿Tu podrías construirme un programa en KumbiaPHP que controlase un árbol genealógico? Debería controlar personas (nacimientos, bodas, divorcios, muerte) que a su vez son hijos (naturales o adoptados) de otras personas y poder mostrar la rama de una persona determinada o el árbol completo. 

Sí. Y, de hecho, KumbiaPHP 1.2.1 encaja bastante bien para hacerlo, porque el problema se presta a separar claramente personas, relaciones familiares y acontecimientos.

Yo lo plantearía como una aplicación web real, no como un simple ejemplo. Podríamos construirla además como proyecto práctico del manual de KumbiaPHP que estamos preparando, de manera que vayamos aplicando casi todo lo aprendido.

Qué debería controlar

La entidad central sería Persona:

Nombre y apellidos.
Sexo.
Fecha y lugar de nacimiento.
Fecha y lugar de fallecimiento.
Fotografía, opcional.
Notas biográficas.

Pero no metería los matrimonios, divorcios y filiaciones directamente como campos de Persona. Son relaciones o acontecimientos y conviene modelarlos independientemente.

Y aquí aparece un problema interesante

Un árbol genealógico no es realmente un árbol en sentido matemático.

Es un grafo.

Por ejemplo:

       A ??? B
        ?   ?
        ??C??

Además, puede haber:

adopciones;
hijos de distintas parejas;
segundos matrimonios;
divorcios;
hermanos por parte de padre;
hermanos por parte de madre;
personas cuyos padres se desconocen;
familias que se cruzan.

Por eso no diseñaría el programa pensando únicamente en una estructura padre -> hijos.

La base de datos debe representar relaciones entre personas, y después el programa construye las distintas vistas genealógicas.

Esto también nos permitiría enseñar en el proyecto cosas muy interesantes de KumbiaPHP: relaciones de modelos, consultas recursivas, validaciones, formularios, sesiones, autenticación, autorización, AJAX, etc.

public function familia($id)
{
    $arbol = Auth::arbolActual();

    if (!$arbol) {
        Flash::error(
            'No hay un árbol activo.'
        );

        return Redirect::to('personas');
    }

    $personas = new Personas();
    
    $persona = $personas->find_first(
        "conditions: arbol_id = {$arbol->id} AND id = " . 
        intval($id)
    );

    if (!$persona) {
        Flash::error(
            'La persona no existe.'
        );

        return Redirect::to(
            'personas/'
        );
    }

    $filiaciones = new Filiaciones();

    /*
     * Progenitores de la persona.
     */
    $progenitores = $filiaciones->find(
        "conditions: hijo_id = " .
        intval($id),
        "order: tipo"
    );

    /*
     * Hijos de la persona.
     */

        "conditions: progenitor_id = " .

        "order: tipo"
    );

    $this->persona = $persona;
    $this->progenitores = $progenitores;
    $this->hijos = $hijos;

$uniones = (new Uniones())->find(

Un detalle importante

No estamos tratando una pareja como si fuera un progenitor o un hijo.

La unión es una relación independiente:

persona ?? unión ?? pareja

Mientras que la filiación es:

progenitor ?? filiación ?? hijo

Eso nos permitirá posteriormente dibujar el árbol correctamente.

Y al pulsar sobre la pareja, hacemos lo mismo que con cualquier otra persona:

personas/arbol/{id}

La pareja pasa a ser la nueva persona central.

¿Qué conseguimos ya?

Podemos navegar:

Juan ? María ? sus progenitores ? sus hijos ? etc.

sin cargar todo el árbol de una vez.

El siguiente paso ya sí sería interesante: dejar de mostrar estos bloques uno debajo de otro y construir la representación visual del árbol, con la persona central en medio, progenitores arriba, hijos abajo y parejas a los lados.
